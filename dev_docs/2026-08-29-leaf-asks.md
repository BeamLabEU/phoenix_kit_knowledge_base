# What we need from Leaf

Notes for Alex, from `phoenix_kit_knowledge_base` on Leaf 0.6.0. Consolidates
the two bugs already sent and adds what we would ask for next, in the order we
would want it.

Short version: **the CRDT is not what we need.** Everything below is cheap by
comparison and fixes failures we have actually reproduced.

## On the CRDT question

> CRDT buys never-lose-a-keystroke and offline merge, at the price of a rewrite
> of the document model — tell me when the use case demands it.

Agreed, and not yet. Two reasons.

**What lost work in our testing was never convergence.** Every failure we
reproduced was between the room and the file on disk, not between two typists —
see the conflict bug below. A CRDT does not touch that: the other party is vim,
git or the Obsidian client, which is not in the document model and never will
be. A vault of markdown files exists so those tools can edit it; "somebody
changed the file underneath the session" is a designed-for event here, not an
edge case.

**And the shape does not call for it.** One room process per note, every session
on a LiveView socket into that single serialization point. Rebasing against one
authority is the right tool for that; CRDTs earn their cost when there is no
single point to serialize through.

What would bring us back asking:

- **Offline editing** — a phone or a laptop that closes mid-sentence and merges
  on reconnect. This is the real trigger; nothing else is close.
- **Measured resync frequency.** "Two people changing the same characters
  converge, but somebody's keystroke loses" is fine as a sentence and
  unacceptable if it fires ten times an hour. `Leaf.Collab.Log` is there to
  see it. We have not measured it, and we would not argue from the sentence
  alone — but if the numbers are bad, that changes the answer.
- **Multi-master**, if a room ever stops being a single process. Ours is
  currently node-local, which is our problem to fix, not yours.

## 1. Tell somebody when a flush is refused

Detail and reproduction: [2026-08-28-leaf-collab-conflict-silent.md](2026-08-28-leaf-collab-conflict-silent.md).

The store contract is right and the room honours it — a `{:error, :conflict}`
does stop it overwriting somebody else's work. What is missing is that nobody is
told, and the work it protected is then discarded.

`conflict: true` goes on the room's state and is read by nothing. No broadcast,
no reply, and `conflict` appears nowhere in `Leaf.Collab`, so no assign changes
and no host hook fires. Then `terminate/2` flushes one last time, conflicts one
last time, and the room dies holding the only copy.

Three fixes, cheapest first, any one of which would do:

- **Broadcast it.** The room has a topic and every session is on it. A
  `{:leaf_conflict, %{document_id:}}` consumed by `Leaf.Collab`'s hook into
  `@leaf_collab.conflict` is all most hosts need to render a banner.
- **Return it from `flush_now/1`** — `{:reply, result, new_state}` rather than a
  hardcoded `:ok`. Nearly free, and makes save-before-navigate honest.
- **Say something on the way down.** `terminate/2` discarding the document after
  a conflict is where work is actually lost. Even a `Logger.warning` with the
  document id turns silent loss into a diagnosable one.

Worth noting the asymmetry: every *other* store error leaves the room dirty so
the next change retries, which is right. Conflict is the one case that can never
recover on its own, and the one nobody is told about.

We work around it by broadcasting from our own store before returning the
conflict. That only works because the store is ours — a host on
`Leaf.Collab.Store.File` has no such hook and gets no warning at all.

## 2. Let a room stop

`Leaf.Collab.Room`'s `{:DOWN, …}` clause drops the departed session from
`people` and returns `{:noreply, …}`. There is no stop, no idle timeout and no
hibernate, so a room started for a note outlives everyone in it and holds that
note's full text plus its operation log for the life of the node. Browsing a
thousand-note vault leaves a thousand processes behind.

We now stop them ourselves (`Collab.close_room/1`), which works but means every
host has to know this and remember to do it — and a host that reads
"rooms are started and supervised by the host … stopped when everybody has
left" in `start_link/1`'s docs will reasonably assume otherwise. That sentence
describes what a host *should* do; it reads as what the room does.

Stopping when the last session leaves, or an idle timeout, would make the
documented behaviour the actual behaviour. If staying up is deliberate — to keep
the operation log warm for a reconnect — then the docs should say so, and an
explicit `Leaf.Collab.Room.stop/1` in the public API would be worth having.

## 3. A rendered `[[wiki-link]]` cannot be clicked

Detail and reproduction: [2026-08-28-leaf-wikilink-click-bug.md](2026-08-28-leaf-wikilink-click-bug.md).

Still open. Summary: `_onWikiLinkClick` is bound to `click` and guards on
`_visualEl.contains(span)`, but hybrid's source swap runs off `selectionchange`,
which a mouse press fires *before* `click`. The block is replaced and the span
detached before the handler runs, so it returns without ever reaching the
modifier check — which is why `follow: :modifier` and `follow: :click` fail
identically and silently.

Capturing the span on `mousedown`, before the selection moves, and acting on it
at `click` would survive the swap.

Also worth reconsidering the default: the comment justifies `:modifier` as "the
gesture Obsidian uses in edit mode", but Obsidian's Live Preview — which is what
hybrid corresponds to — follows a plain click. That is what our user expected
and asked for. Not blocking us; we set `:click` explicitly.

## Not asks, just so you know

- `Leaf.Collab.Store.File` fits our storage model exactly — hash on read,
  checked before write, conflict rather than overwrite — but we cannot use it,
  because it writes the file and stops there. A note's title, front matter,
  tags, links and search vector are all derived from its bytes, so we persist
  through our own context instead. The seam is right; the reference
  implementation just cannot know about an index.
- `Leaf.Collab.Room`'s moduledoc still describes itself as the collaboration
  testbed where "`base_length` mismatches are recorded rather than resolved".
  `rebase_over/2` and the refusal path are in the same file. The docs undersell
  the code, and we nearly believed them.
