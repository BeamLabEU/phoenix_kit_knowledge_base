## Built

**Storage.** Filesystem canonical, Postgres as index. A vault is a directory, a
folder is a directory, a note is `<Title>.md`. Path containment enforced twice
(string validation, then expanded-path re-check), symlinks inside a vault skipped
rather than followed, atomic writes via temp-file-plus-rename.

**Vaults.** System and personal, sharing one `owner`/`editor`/`viewer` membership
model. `knowledge_base.manage_system_vaults` confers ownership of every system
vault and deliberately grants nothing over personal ones.

**Links.** `[[wiki-links]]` with aliases and heading anchors. Backlinks panel.
Unresolved-link list ordered by how many notes want each missing title. Creating
a note retroactively resolves every link waiting for it; deleting one turns links
back into unresolved rather than dropping the mentions. Ambiguous titles resolve
same-folder → shortest-path → alphabetical, with `[[folder/Note]]` to be explicit.

**Rescan.** Reconciles index with disk. Compares `(mtime, size)` before hashing,
so a large vault stays cheap and a `touch` costs one read. **Renames detected by
content hash**, so `mv` in a shell preserves a note's uuid and every backlink.
Available as `mix phoenix_kit_knowledge_base.rescan [slug] [--quiet]`, exiting
non-zero on error so cron fails loudly.

**Safety.** Stale-write guard hashes the file before every write and refuses when
it moved, offering reload-or-overwrite. Trash: deletes move to `.trash/<unique>/`
with the original path preserved, so restore is a move.

**Sync.** Per-vault PubSub. Note saves, deletes, folder changes and rescans reach
every open session, with origin tracking so a browser ignores its own writes. A
rescan emits one message, not one per file.

**Editing.** Leaf in hybrid mode — one surface, as in Obsidian. `[[` and `#`
inline-suggestion triggers, with ambiguous titles inserted path-qualified.

## Verification

Three layers, because no single one was sufficient:

1. **156 database-free tests** — markdown parsing, path containment and filename
   rules against a real temp directory, link tie-breaking, editor identity,
   changeset invariants, behaviour compliance, route ordering, migration
   versioning.
2. **Live-database scripts** — indexing, rescan, rename detection, the stale
   guard, PubSub fan-out, trash round-trip, all run against the dev Postgres.
3. **`scripts/smoke_http.exs`** — forges a session cookie and renders every page
   as a logged-in user.

Layer 3 exists because of a bug that got through layers 1 and 2. See below.

## Bugs found, and where they hid

| Bug | Found by | Why it was invisible |
|---|---|---|
| Search entirely broken — `websearch_to_tsquery`'s first argument is a `regconfig`, so a bound parameter is typed as an OID and Postgrex refuses it | live DB script | Compiles fine; the DB-free suite never runs a query |
| Duplicate titles crashed the LiveView — a constraint violation inside a transaction returned `{:error, :rollback}`, discarding the changeset | live DB script | Needs a real unique-index violation |
| Two notes showed the same content — Leaf's surfaces are `phx-update="ignore"`, so a constant component id reused the hook across notes | **the user, in the browser** | Purely client-side DOM state |
| A debounced edit could be saved into the *next* note opened | found while fixing the above | Timing-dependent; would have silently corrupted a file |
| `BadBooleanError` crashed every vault page — `nil and …` where `:if={@x}` alone was fine | **the user, in the browser** | The DB-free suite has no endpoint, and unauthenticated `curl` never gets past the login redirect |
| Two deletions in the same second overwrote the first trashed copy | a test written for it | Second-resolution timestamps |
| Autosave silently overwrote a colleague's edit once a conflict was flagged | re-reading my own code while answering a question about multi-user | The comment claimed "saving again is explicit" — untrue under autosave |

Two of these reached the user. Both were in surfaces the automated checks could
not reach, and the `curl` health check I had been reporting as green only ever
proved a route existed. `scripts/smoke_http.exs` closes that specific hole.

## Decisions revised during the day

- **Editor**: core's `MarkdownEditor` → **Leaf**. I checked the wrong component
  and told the user PhoenixKit had no live preview. It does.
- **Storage**: database-backed → **filesystem canonical**. The user caught that I
  had never asked where notes live.
- **Reading view**: added, then removed. Obsidian has no view/edit split.
- **File names**: silently sanitised → **rejected with a reason**. Quietly filing
  `Ideas: Part 2` as `Ideas Part 2` is worse than an error message.

## Open

- **FK to `phoenix_kit_users`.** `vault_members.user_uuid` has a real foreign key
  with `on_delete: :delete_all`; `phoenix_kit_boards` and `phoenix_kit_inbox` both
  use a bare `:binary_id` instead. Defensible — theirs is attribution, ours is
  authorization, and an orphaned membership row is a dangling permission — but it
  is a deviation from the sibling convention. Awaiting a call.
- **Front matter through Leaf's hybrid mode** has not been eyeballed in a
  browser. Visual and HTML modes are denied because they round-trip through HTML
  and would destroy a `---` block; hybrid edits the source directly and should be
  safe, but "should be" is doing work in that sentence.
